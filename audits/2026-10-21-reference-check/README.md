# seo-suite 参考文件核对（2026-10-18 至 2026-10-21）

这一轮把 `skills/seo-suite/` 的 129 份参考文件和 25 份输出模板逐条对一手来源核了一遍：错的改正，没依据的删掉，空泛段落改成检查清单。本目录是核对记录，安装 skill 时不会带上。

## 判据（动手前写定）

- **V 核实**：打开一手来源，读到对应句子。文件里补链接，并写「核对 2026-10-21」。
- **F 改正**：来源说法不同，按来源改写。
- **D 删除**：找不到一手来源或可信的第三方来源，就删除。方法类说法改标「本套件口径」，去掉伪精确数字。
- **K 本套件口径**：这是本套件自己的设计约定，不是对外部世界的断言。
- **未核**：来源打不开，措辞降级，不写成事实。
- 一手来源包括：Google Search Central、web.dev 与 CrUX 文档、Bing Webmaster、Yandex Webmaster、Naver Search Advisor、schema.org、W3C/WHATWG/IETF、各 AI 爬虫的官方文档、平台官方帮助、论文原文、统计机构原始页面。第三方研究可以留，但要标「第三方」，并写明样本和时间。

通过标准：
1. 每份文件都有账本行。
2. 独立抽查 30 条 V，至少 27 条能在原文读到对应句子。
3. 抽查 20 条 F/D，全部已在文件里体现。
4. 文件里提到的脚本参数都真实存在。
5. `self_check.py` 全绿，`link_check.py` 无死链。

## 文件

- `ledger.csv`：证据账本。列为 `file, section, claim, verdict, source_url, source_type, checked_date, note, batch`。`source_url` 不是网址时，表示核的是本仓的脚本源码或 `--help`。
- `spotcheck.csv`：独立抽查结果。列为 `kind, _ledger, file, claim, result, evidence`。
- `script-params.csv`：参数核对明细。每行是一处参数提及，`status` 取值：`ok_help` 表示在顶层 `--help` 里查到，`ok_sub` 表示在子命令 `--help` 里查到。
