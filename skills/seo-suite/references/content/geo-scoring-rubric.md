# AI 回答五维可见性打分卡(geo-scoring-rubric)

> 建立于 2026-10-10;2026-10-18 对照来源复核。**全部权重、锚点和 cap 都是本套件口径,没有实证依据**。
> 来源:[oneglanse](https://github.com/oneglanse/oneglanse)(MIT)的 `packages/services/src/analysis/analysisPrompt.ts`
> (441 行)。照搬的部分:五维权重 25/25/20/15/15;三条 cap(只有 1 次提及 ≤50、对比性负面 ≤35、
> 只在问句里 ≤10);拒答/回声先过闸;全文绝对排名;「pretty good 不是 80+、平均列名不是 70+」。
> 本套件改动的部分:原文各维是区间锚点,本卡改成单点分值;B 维改用排名映射 #1→100/#2→85/#3→70/
> #4→55/#5→40/#6+→30(原文排名分量是 100/80/65/50/40/30);原文总分还平均情感和推荐两项,本卡的
> geo_score 只算五维可见度。相关方法另见 [borrow-specs.md B4](../research/borrow-specs.md)。
> 本卡打的是**单条 AI 回答里品牌的呈现质量**,是描述性测量——不是引擎内部信号,
> 不预测引用、流量或转化(第十二节)。改数值要同时改 `scripts/citation_panel.py` 里的
> `GEO_RUBRIC_DIGEST` 与 cap 常量,两处必须一致。

## 一、适用场景与执行方式

- 对象:`citation_panel.py` 采样到的**单条** AI 回答原文(一个 prompt × 一个引擎 × 一次采样)。
- 执行者:人或 agent。脚本只负责采样与留档(`mentioned/cited/state` 三列),打分是
  **语义任务**——判断"品牌在这条回答里被如何呈现",无法由正则完成。
- 产出:一个 0-100 的 geo_score 加结构化判定(第十一节 schema),写回 run 文件的
  扩展键;不改动 citation_panel 的五状态口径。
- 边界:只对留档了完整原文(含引用列表)的 cell 打分;凭记忆事后补打一律作废。

## 二、回答质量闸(先过闸,再打分)

| 闸 | 判定 | 处置 |
|---|---|---|
| refusal | 引擎明确拒答/回避(安全策略、宣称无立场、要求换问法) | 不打分;presence=refused;面板 state 记 no_answer(留覆盖分母计 zero-presence,**不是 failed**) |
| no_answer | 引擎没给出答案体 | 不打分;同 no_answer 口径 |
| echo_only | 品牌名只出现在**复述用户问题**的回声句里("关于 Acme 与……的比较") | 不算提及;presence=echo_only;面板 mentioned=0(state=brand_absent) |
| substantive | 有实质回答体 | 进入第三节打分 |

回声判定要点:回声句通常紧跟问题、以问句复述或"Let's compare…"式引导出现;
品牌在**论证部分**(推荐理由、对比结论、事实陈述)零出现 = echo_only。

## 三、五维 visibility 加权表

总分 = Σ(维度分 × 权重),再过第四节硬 cap。各维 0-100。

| 维度 | 权重 | 测什么 |
|---|---|---|
| A 覆盖 | 25% | 品牌被讨论的完整度 |
| B 首现位置 | 25% | 品牌首次出现离答案开头多早(取第五节绝对排名映射) |
| C 结构显著性 | 20% | 提及处的排版层级(标题/加粗/列表 vs 行文埋没) |
| D 频次 | 15% | 全文提及次数(回声不计入) |
| E 语境角色 | 15% | 被推荐 / 被并列比较 / 被警告 |

**A 覆盖 六档锚点**(每档一句判定):

| 分 | 判定 |
|---|---|
| 0 | 品牌完全未被提及 |
| 20 | 仅品牌名出现,无任何属性描述(纯列名) |
| 40 | 提及 + 单一属性(一个功能、一个价位或一个定位词) |
| 60 | 提及 + 2-3 个属性维度(功能/价格/定位/人群任取二三) |
| 80 | 多属性 + 具体事实(数字、版本、客户量、差异化对比点) |
| 100 | 专属小节级讨论:定位/功能/价格/适用人群多线展开且含具体事实 |

**B 首现位置**:分值 = 第五节绝对排名映射(#1→100 … #6+→30)。
若映射分与首现深度明显矛盾(如排 #1 却首次出现在文末),先怀疑排名数错,复核读序。

**C 结构显著性 五档**:100 标题级(H2/H3 或加粗强调处,品牌是该结构块的主题)/
80 列表或表格条目主体 / 60 段首句或对比表列名 / 40 行文中段 / 20 长段落深处埋没
(需逐句找)。

**D 频次**:1 次=30 / 2-3 次=55 / 4-5 次=75 / ≥6 次=90(1 次另触发第四节 cap)。

**E 语境角色**:100 明确推荐(首选/"最适合 X")/ 80 正向对比胜出或作为代表方案
展开 / 60 中立并列比较之一 / 40 仅作反例或注意事项、无否定 / 20 被警告或指出重大
缺陷 / 0 被明确劝退("不推荐/避免使用")。

## 四、硬 cap 表(加权分出来后先过这张表)

| 条件 | 总分上限 |
|---|---|
| 仅 1 次提及 | ≤ 50 |
| 只出现在问题/回声里 | ≤ 10 |
| 对比性负面提及(在对比语境中被点名批评或劝退) | ≤ 35 |

多条命中取最严。cap 是**封顶不是扣分**:加权 72 但仅 1 次提及 → 记 50,不是 72−22。

## 五、绝对排名(全文读序,不是小节名次)

- 把回答全文(含推荐列表、对比表,不含问题回显)按**首次出现读序**给每个品牌编号。
- **子类目第 1 ≠ 全文第 1**。示例(全文读序:HubSpot→Zoho→Pipedrive→Acme):

```
全文排名:        #1 HubSpot   #2 Zoho   #3 Pipedrive   #4 Acme
"中小团队"小节:   Zoho, Acme   ← 小节内 Zoho 在前
正确: Acme 绝对排名 #4(全文读序第 4 个首次出现的品牌)
错误: 给 Acme 记"小节 #2",或给 Zoho 记"#1(小节第一)"——小节名次不进任何字段
```

- rank→分值映射(B 维直接取用):#1→100 / #2→85 / #3→70 / #4→55 / #5→40 / #6+→30。

## 六、情感校准表(5 区间,决策树自上而下)

```
1. 有显式最高级/强推荐词(best/top pick/首选/最适合/最值得)? → 81-100;没有 → 封顶 79
2. 同屏列出 pro+con? → ≤ 79(即便优点条目更多)
3. 纯列表条目、无任何评价词? → 50-55
4. 负向词表为主导评价? → 21-45(主导且被明确劝退 → 0-20)
5. 其余:正向但无最高级 61-80;中性描述 56-60
```

负向词表(判负的典型触发):expensive/overpriced、buggy、难用/学习曲线陡、
not recommended/avoid/慎选、投诉多、已停止支持、安全事件。
"贵"单独出现且语境为"功能全但贵" → 按混合(21-45)计,不直落 0-20。

## 七、recommendation 六级

| 级 | 判定 |
|---|---|
| top_pick | **全文级绝对排名 #1 + 显式最高级措辞**,两者缺一降 recommended |
| recommended | 进入围推荐名单或获正向推荐语,但非首选 |
| honorable_mention(=mentioned_only) | 被列名/提及,无推荐语也无贬语 |
| neutral | 被并列比较,评价中性 |
| discouraged | 上榜但主要评价为负面或被劝退 |
| absent | 未被提及(含 echo_only——回声不算) |

## 八、竞品去重(competitors[] 打分前先合并)

- 子产品合并到父品牌:Zoho CRM + Bigin → Zoho;HubSpot Marketing Hub + Service Hub → HubSpot。
- 合并后取**各子产品最早的绝对位次**为父品牌位次。
- 情感 = 各子产品情感按提及次数加权平均,四舍五入到整数。
- 去重先于排名编号:先合并、再按全文读序编号,避免父品牌被拆成两个名次。

## 九、反通胀纪律

LLM(和人)打分**系统性偏高**。两条底线:

- "pretty good / decent / 挺不错"不是 80+,落在 61-75;
- **平均列名不是 70+**——"与其他 5 个工具并列、无评价词"的回答,总分就该在
  45-55 一带,被列名本身不加分。

输出前交叉验证清单(12 条全查,以下 8 条最关键):

1. 每个维度分都有原文引文支撑?找不到引文的维度重打,不猜。
2. B 维分来自全文绝对排名,而非小节/列表内名次?
3. 仅 1 次提及的回答,总分是否已压到 ≤50?
4. 回声/复述里的品牌名是否已全部剔除(不进 mentions 计数)?
5. 情感 81+ 的回答,原文确有显式最高级词?pro+con 并列是否已压到 ≤79?
6. 竞品子产品是否已合并到父品牌再排名?
7. refused/echo_only 是否走了质量闸而非打分流程?
8. 本批打分分布是否通胀(一批回答大多 70+ → 回到锚点重校,而非顺手下调)?

## 十、风险五型(risks[] 枚举)

| 型 | 判定 |
|---|---|
| outdated_info | 回答依赖已过时事实(停售产品、旧价格、旧版本号、已下线功能) |
| factual_error | 功能/参数/归属陈述与可核验事实相悖 |
| brand_confusion | 把他品能力/数据安到本品牌,或反之,或与同名实体混淆 |
| negative_association | 品牌与负面语境绑定(故障、诉讼、安全事件、差评潮) |
| missing_from_response | 问句点名本品牌或其核心品类,回答整体缺席 |

## 十一、输出 schema(写回 citation_panel run 扩展列)

打分结果写入 `runs/<run_id>.json` 的 `results.<prompt>.geo` 键(panel 聚合忽略未知键,
coverage/share 口径不受影响):

```json
{
  "geo_score": 48,
  "presence": "name_only_mention",
  "position": {"absolute_rank": 4, "mentions": 1, "first_occurrence_pct": 62},
  "sentiment": 53,
  "recommendation": "honorable_mention",
  "competitors": [
    {"brand": "HubSpot", "absolute_rank": 1, "mentions": 5, "sentiment": 82},
    {"brand": "Zoho", "absolute_rank": 2, "mentions": 3, "sentiment": 68}
  ],
  "risks": ["outdated_info"]
}
```

- `presence` ∈ refused | no_answer | echo_only | brand_absent | name_only_mention |
  cited_brand。写回面板 `state` 列的映射:refused→no_answer、echo_only→brand_absent,
  其余同名(细粒度值只活在 geo 块里)。
- refused / no_answer / echo_only / brand_absent 不产出 geo_score(记 null),不进入
  任何平均——缺席不是 0 分回答,是没有可打分的呈现。
- 示例自洽性:A=20(纯列名)×0.25 + B=55(#4)×0.25 + C=80(列表条目)×0.20 +
  D=30(1 次)×0.15 + E=60(中立并列)×0.15 = 48.25 → 48(1 次提及 cap≤50 未再压)。

## 十二、与 geo-evidence.md 的对齐声明

- **描述性测量,非因果承诺**:geo_score 衡量"这条回答如何呈现品牌",不预测也不
  承诺引用、流量或转化;高分不写入实施验收或预算收益(geo-evidence 营销转述纪律)。
- 证据阶梯不坍缩:retrieved→cited→mentioned→recommended→converted 是不同层级
  ([geo-evidence.md](geo-evidence.md) 第八节六级阶梯);本卡的 recommendation 字段只覆盖
  mentioned→recommended,不把"被提及"说成"被推荐",更不合并成一句"AI 可见性提升"。
- **采样 3 次取多数**:与 citation_panel"同一 prompt ≥3 次采样才报"同口径。单次回答会随
  运行变化([arXiv 2604.07585](https://arxiv.org/abs/2604.07585) 主张把可见度当分布测),
  prompt 级结论取 3 次采样 geo_score 的多数档,分歧大 → 标 unstable。
- **failed 不入分母**:采集失败的 cell 不打分、不进任何聚合,与面板口径一致。
- 判分指令本身会改变同一回答的得分([arXiv 2609.06811](https://arxiv.org/abs/2609.06811))。
  本卡固定措辞与锚点;调整须留档、重打历史样本对比分布,不为让某次结果好看而单点改锚。

## 十三、检查清单

| # | 检查什么 | 怎么查 | 通过 / 失败 |
|---|---|---|---|
| 1 | 打分口径与脚本一致 | `python3 scripts/citation_panel.py score --rubric` 打印代码内要点,与本卡第三至七节逐条比对 | 通过:权重、cap、映射一致。失败:任一数值不同(两处要同批改) |
| 2 | 只给有原文的 cell 打分 | 每条打分附回答原文与引用列表的留档位置 | 通过:每个维度分都能指到原文引句。失败:凭记忆补打 |
| 3 | 硬规则不违例 | `python3 scripts/citation_panel.py score --last --scores scores.json` | 通过:无硬违例(有违例时脚本整批拒绝,不落盘)。失败:脚本报错 |
| 4 | 不通胀 | `python3 scripts/citation_panel.py report` 看 GEO 打分聚合节 | 通过:分数分布没有挤在 70+;均值高于 75 时回锚点重校。失败:一批回答大多 70+ 而原文没有最高级措辞 |
| 5 | 稳定性 | 同一 prompt × 引擎至少 3 次采样 | 通过:多数档一致,否则标 unstable。失败:单次打分就写结论 |
| 6 | 报告措辞 | 读报告文本 | 通过:写「描述性测量」,按引擎分列。失败:写成「AI 可见性提升 X%」或跨引擎平均 |
