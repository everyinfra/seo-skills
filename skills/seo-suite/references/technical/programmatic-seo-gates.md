# 程序化 SEO 质量闸门

> 建立于 2026-10-09。阈值参考 [AgriciDaniel/claude-seo](https://github.com/AgriciDaniel/claude-seo)（MIT）`skills/seo-programmatic/SKILL.md` 与 `skills/seo/references/quality-gates.md`。按本套件证据约束改写。
> 背景：Google 的 scaled-content-abuse 政策针对"大量无独立价值页"，这些闸门是风险控制，不是流量保证。

## 一、核心闸门（数字硬规则）

| 指标 | 阈值 | 动作 |
|---|---|---|
| 未复核页 | **100+** | WARNING：发布前须内容审计 |
| 无正当理由页 | **500+** | **硬停**：需用户明确批准 + 薄内容审计 |
| 页间唯一内容 | **<40%** | 标记薄内容（惩罚风险） |
| 页间唯一内容 | **<30%** | 硬停（增强规则） |
| 单页字数 | <300 | 标记复核 |
| 近重复记录 | 字段重合 >80% | 标记 |

唯一度计算：`(该页独有词 / 该页总词) × 100`，对照集内全部其他页；公共头脚导航排除，模板样板计入。

## 二、发布纪律

- 人工抽检 **≥5–10%** 样本
- 分批上线：每批 **50–100 页**，观察 **2–4 周**再下一批
- **绝不一次性发布 500+ 未审页**

## 三、页型地板（字数/唯一度）

| 页型 | 字数下限 | 唯一度下限 |
|---|---|---|
| 主页 | 500 | 100% |
| 服务页 | 800 | 100% |
| 位置页（主） | 600 | 60% |
| 位置页（次） | 500 | 40% |
| 博客 | 1,500 | 100% |
| 产品页 | 400 | 80% |
| 分类页 | 400 | 100% |
| About / 落地页 | 400–600 | 100% |

位置页专则：**30+ WARNING**（强制 60%+ 唯一）、**50+ 硬停**（需正当理由）。"换城测试"：换掉城市名内容仍成立的页是 doorway。

## 四、安全 vs 风险页型

**安全（可规模化）**：集成页（真实设置文档+API 细节+截图）、模板/工具页（可下载）、词表（200+ 词定义）、产品页（独特规格/评论/对比）、数据页（独有统计/图表）。
**风险（惩罚候选）**：仅换城市的地点页、无行业价值的 "Best [tool] for [industry]"、无对比数据的 "[竞品] alternative"、未审 AI 生成内容、**模板样板 >60%** 的页。

## 五、URL 与内链规则

- 小写连字符 slug；生成时强制唯一；**<100 字符**；主内容 URL 不带 query 参数；尾斜杠一致
- 内链 3–5 条/千词；自动关联 3–5 个相关页；hub/spoke 结构配 BreadcrumbList
- Sitemap 在 **50,000 URL / 50MB** 拆分（先到先拆）；`<lastmod>` 用数据更新时间戳；noindex 页不入 sitemap

## 六、索引膨胀控制

- 未过闸门的页 noindex
- 仅真重复/低价值筛选视图做 noindex/canonical 合并
- **>10k** 程序化页的站监控抓取统计
- 月度"已索引 vs 应索引"审计
- 薄记录合并入聚合页

## 八、goose pSEO 模式:竞品逆向与模式闸门(gooseworks 深读,2026-10-09)

质量闸门(上文)管"怎么做不出事";goose 的两个 skill 补"选什么模式值得做"——先逆向竞品,再给模式打分。

**第一步:URL 模式正则分类表**(pSEO-spy,爬竞品 sitemap 后按此聚类):

| 正则 | 页型 | 数据轴 |
|---|---|---|
| `/vs/.*`、`/compare/.*` | 对比 | 竞品名 |
| `/integrations?/.*` | 集成 | 工具/App 名 |
| `/for-.*`、`/solutions/.*` | 垂直行业 | 行业名 |
| `/use-cases?/.*` | 用例 | 任务场景 |
| `/alternatives?(-to)?/.*` | 替代 | 竞品名 |
| `/templates?/`、`/examples?/` | 模板 | 模板类型 |
| `/glossary/`、`/what-is/` | 词汇 | 术语 |
| `/tools?/`、`/calculat(or\|e)/` | 工具 | 工具功能 |
| `/blog/.*` | 编辑内容(**排除出 pSEO 分析**) | — |

每模式记:页数/数据轴(每页变什么)/URL 一致性/**覆盖完整度**(明显的变体做满没有)。

**程序化 vs 编辑四分类**:Programmatic(URL 结构一致+标题同构+高页数+结构化内容)/Semi(模板+重手工定制)/Editorial(单篇手写)/Auto-generated thin(标签页/归档页)——**只对前两类做分析**,thin 类直接记惩罚风险。

**模板质量 7 维打分**(每维 1-5,每模式抽 3-5 页:高变体/低变体/中间各一):内容深度/每页独有价值(离开模板还剩什么)/数据丰富度(表格/对比/统计/截图)/新鲜度信号(更新日期/现价)/内链(hub 结构)/CTA 融合(场景化 vs 通用横幅)/schema(FAQ/review)。**三档结论**:4-5 均分=执行良好,难撼动;3-4=可改进,"用更好模板打赢"是机会;1-3=薄,"轻松碾压"。

**缺口四型**(pSEO-spy Phase 5):模式覆盖矩阵(模式×竞品×页数×质量星级)后分——①**白空间**(整个模式无竞品建,最高机会,先验证需求存在)②**变体缺口**(竞品在做某模式但没做满:没写的 vs 对手/没建页的集成/没覆盖的行业=快赢入口)③**质量缺口**(竞品有页但薄:<500 词/无独有数据/过时/无 schema/页面间无视觉区分——"out-template"机会)④正面强攻(硬撼 4-5 分模板,高成本)。

**模式评分权重**(pSEO-planner,决定建不建):搜索需求 30%(全变体可寻址量)/意图质量 25%(vs/=高购买意图,glossary=低)/模板可行性 20%(能否从模板产出有差异化的有用页)/数据可得性 15%(变量数据能否程序化获取)/竞争缺口 10%(没人做或做得烂)。**评分 ≥50 的模式逐个过可行性三问**:数据源在哪(竞品名单=手工有限高价值/集成名录=API/行业表=标准列表)/内容差异化怎么做(vs/ 页要真实功能对比不是"我们更好";集成页要真设置指南;垂直页要行业特定痛点)/CMS 能不能规模化(静态生成器 Next.js/Astro=优;Webflow CMS 单集合上限 10K 条;WordPress 自定义文章类型=可;纯手工=不是 pSEO)。

**vs/ 模板蓝图八段**(planner,可作所有对比页基准):①TL;DR 三句话(首屏)②快速对比表(功能矩阵勾叉)③详细对比 4-6 维度各 2-3 段④价格逐档对比⑤谁该选我们(ICP 描述)⑥谁该选对方(公平评估)⑦真实用户评价(双边引语)⑧CTA。每页数据需求:竞品功能数组(来自其官网/文档)/价格对象/评论数组(G2/Capterra)/按竞品定制的差异化数组。硬要求:≥1500 词、≥1 条独有洞察(不是功能清单)、能用截图/图就用、**季度更新**(价格/功能会变)。

**流量归因两模式**(判定"该模式真带量"还是"只是存在"):增强模式=拉域的 ranked_keywords 按 URL contains `/vs/` 等过滤,得每模式的排名词数/估算流量/均位/最佳变体页/KD 分布;基线模式(无 API)=每模式 spot-check 3-5 页 `web_search` 看是否 top-10+`site:domain/vs/` 查索引率,流量指示=页数×索引率×DA 代理,**明标方向性估算**。优先级矩阵:P0=白空间+质量缺口(低努力)、P1=变体缺口、P2=正面强攻。
