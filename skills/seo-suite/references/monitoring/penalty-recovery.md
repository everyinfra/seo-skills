# 惩罚识别与恢复手册(类型学·鉴别诊断·恢复流程·负面 SEO 防御)

> 建立于 2026-10-09。定位:Google 惩罚的**全生命周期处置**——识别(什么类型的罚)→鉴别(手动还是算法)→恢复(reconsideration / 内容工程)→防御(负面 SEO)。
> 分工(引用不重复):**时间线对齐与算法归因方法论**见 [seo-drift-monitoring](seo-drift-monitoring.md) 第五节(归因流程)与五层协议 L5;**站群/PBN 处罚案例模式、传染性与 SRA 时间线**见 [site-networks](../research/site-networks.md) 第四节;**disavow 判定门槛**见 [外链画像分析](../research/backlink-profile-analysis.md) 第四节;**规模化内容政策闸门**见 [agent-readiness](../technical/agent-readiness.md) 第 8 节。本文件只写上述文件未覆盖的:手动动作类型全清单、reconsideration 全流程、负面 SEO 防御、恢复期策略与时长汇总。

## 一、惩罚类型学:手动动作全清单

### 1.1 清单口径

- 唯一权威入口:GSC「Security & Manual Actions → Manual actions」报告(2026-10 核对:官方类型清单自 2024-05 增补 Site reputation abuse 后**未再新增类型**;cloaked images/sneaky mobile redirects 等旧类型已并入 cloaking 家族表述)。
- 手动动作有邮件通知+GSC 站内记录;**报告里看不到任何条目=没有手动动作**(哪怕流量腰斩——那是算法或技术,见二)。

### 1.2 全类型表(触发条件×识别信号)

| # | 手动动作 | 触发条件(人工评审判定) | 站长侧识别信号 |
|---|---|---|---|
| 1 | **Pure spam(纯垃圾)** | 站点几乎全无价值:自动生成/采集/堆砌混装,无可救部分 | 整站去索引,`site:` 大幅缩水;GSC 报告标 site-wide;最重处罚 |
| 2 | **Hidden text / keyword stuffing(隐藏文本/关键字堆砌)** | 白底白字/字体缩到 1px/CSS 移出屏外藏词;正文异常重复关键词 | 选中文本高亮或看渲染 CSS 才见隐藏内容;页面文本/词频比异常 |
| 3 | **Spammy structured markup(垃圾结构化标记)** | schema 标记用户看不见的内容、评分/价格与页面不符、标记他人内容 | 富结果消失+GSC 富结果报告异常;比对渲染内容与 JSON-LD 字段 |
| 4 | **Unnatural links to your site(链接方案·买入侧)** | 购链/交换链/自动建链指向本站(PBN、卫星站、赞助文未标注) | GSC 报告+外链档案锚文本精确匹配异常密集;[外链画像分析](../research/backlink-profile-analysis.md) 七因子低分 |
| 5 | **Unnatural links from your site(链接方案·卖出侧)** | 本站大量向外售出/交换链接(含页脚全站挂链) | 出站链接清单里 sitewide 锚文本链接、非编辑理由的导出 |
| 6 | **User-generated spam(用户生成垃圾)** | 论坛帖/评论/个人资料页被灌垃圾,宿主未治理 | GSC 报告通常 partial;UGC 区段大量垃圾文本与外链 |
| 7 | **Cloaking / sneaky redirects(隐藏与欺骗性重定向)** | 给爬虫与用户返回不同内容;用户点 A 被 JS/meta 跳到无关 B | 用 URL Inspection 的"查看抓取页面"对比真实浏览器渲染;历史遗留子类型(隐藏图片/移动端跳转)现并入本类 |
| 8 | **Scraped content / thin value / doorway(采集与薄价值)** | 主体为采集改写、无独立价值;doorway 城市页农场批量占位 | 整组页面同时掉出索引;内容与源站高度雷同(换城测试不过,[site-type-templates](../technical/site-type-templates.md) 闸门口径) |
| 9 | **Scaled content abuse(规模化内容滥用)** | 自动化/AI 批量产页无独立价值(非"用了 AI"而是"无价值") | 2025-06 起成批处罚(时间线见 [agent-readiness](../technical/agent-readiness.md) 第 8 节);模板页唯一内容 <30% 是硬停线 |
| 10 | **Site reputation abuse(网站声誉滥用)** | 借宿主站权威挂无编辑监督的第三方板块为排名目的(2024-05 立规) | **受影响板块**流量归零、编辑部正常;2026-08-30 起 EEA 内改板块独立排序(分区域表述纪律见 [site-networks](../research/site-networks.md) 4.3) |
| 11 | **Hacked 与安全类(security issues,独立报告)** | 恶意软件/注入垃圾页/钓鱼;被黑站常连带垃圾页面动作 | 浏览器与 SERP 警示标签;日志里有异常新增 URL;处置走安全事件而非本手册第三节流量路径 |

- **口径纪律**:上表是识别用速查,不是处罚判定器——判定只认 GSC 报告原文;表中"识别信号"用于报告之外的预诊与审计。

### 1.3 匹配范围:site-wide vs partial

- GSC 每条动作标 **Site-wide matches**(全站)或 **Partial matches**(仅样例 URL 及同类页)。partial 只处理受影响板块即可申诉,牵连面小得多。
- SRA 的特殊形态:处罚落在"第三方板块"这一层([site-networks](../research/site-networks.md) 4.4 已列速查行,此处不重复)。

### 1.4 手动动作报告的读取五字段

打开一条动作记录,按序读五件事,直接决定三节的处置路径:

| 字段 | 读什么 | 决定什么 |
|---|---|---|
| Issue type | 动作类型(1.2 表的行号) | 修复动作族(内容类/链接类/结构化数据类) |
| Matches | Site-wide / Partial | 修复面=全站还是板块——工作量与审核周期量级 |
| Example URLs | 官方给的违规样例 | 仅是**样例**:partial 类必须按"同类页全量"扩展修复面 |
| Last notified | 通知时间 | 与流量下降日交叉验证(2.1 时间轴) |
| Resolve | 「Request review」入口状态 | 是否已在申诉流程中(接手存量客户时常见"已提交未处理") |

- **接手存量站的第一课**:先看有没有**历史已撤销**的动作记录——撤销过=该站进过人工复审视野,再犯的处罚会更重,处置预算要上浮。

## 二、算法性损失 vs 手动动作:鉴别诊断

> 本节只讲判别框架;时间线对齐五步法、传感器面板、五层协议 L1-L5 **全部沿用** [seo-drift-monitoring](seo-drift-monitoring.md) 第五节与「流量诊断五层协议」,不在此重复。

### 2.1 三证据轴判别

| 证据轴 | 指向手动动作 | 指向算法性损失 |
|---|---|---|
| **GSC 通知** | Manual actions 报告有条目+邮件 | 报告干净(算法永不发通知) |
| **时间线对齐** | 下降日与算法公告**不对齐**——人工评审随机排期,与更新窗口无关 | 下降首日落在更新 rollout 窗口内或紧邻(end+7 天宽限口径见 drift-monitoring 五) |
| **下降形态** | 与违规面同构:partial 只砸违规板块,site-wide 整站;常伴去索引 | 全站或整类页面按比例滑落,索引量正常;SERP 里同轮大量站点同步波动(传感器旁证) |

### 2.2 两条铁律

1. **先开 GSC 再谈归因**:五层协议 L5 里"处罚"分支的第一动作就是查手动动作报告——空报告直接把诊断推向算法/技术/竞品三向。
2. **手动动作可以与算法性损失叠加**:撤销手动动作≠排名回归,若同站还有算法性质量问题,恢复要等下一轮 core(见 3.2/6.1)。这是"撤销了还不涨"的第一解释,不是"申诉失败"。

### 2.3 判别决策树(把三轴串起来)

```
流量/排名显著下滑
├─ 先跑 L1-L4(数据真实性→定位→页面级→技术)——全部净了才进惩罚分支
├─ GSC Manual actions 报告有条目?
│   ├─ 有 → 手动动作:按类型进三·3.1;叠加检查算法时间线(2.2 铁律 2)
│   └─ 无 → 算法性/竞品/需求三分:
│       ├─ 下降首日落在更新窗口(或 end+7 天宽限)→ 算法性:进三·3.4
│       ├─ impressions 平+clicks 降 → 不是惩罚,是 SERP 特性/竞品截流(drift-monitoring 五第 5 步)
│       └─ 无更新对齐、无报告条目、全站滑落 → 未确认波动:按 drift-monitoring 五"结论时点"等 1-2 周,不强行归因
```

- 树的每一层出口都有数据动作,没有"感觉像被罚了"这类出口;诊断不清时执行 drift-monitoring「诊断清单细化」节的 4 步协议(列假设→两利动作→区分性数据→采集计划)。

### 2.4 易混淆情形

- **spam update 打击 vs 手动动作**:spam update(算法)无通知、按更新窗口对齐;手动垃圾动作有 GSC 条目——2026-09 spam update 后手动动作数量走高(PPC Land 口径),两类同期出现时更要用报告区分。
- **技术事故**:2024-08-15 官方 ranking bug 证明技术事故可与算法混淆,对齐自家发布日历(drift-monitoring 五第 3 步)后再谈惩罚。
- **Yandex/百度口径**:Yandex 滤镜(Минусинск 类)与百度低质屏蔽是各自生态的"算法惩罚",鉴别入口与时长数据见 [site-networks](../research/site-networks.md) 4.1(不重复)。

## 三、恢复手册

### 3.1 手动动作:修复→Reconsideration 全流程

1. **定位范围**:GSC 报告读三件——动作类型、匹配范围(site-wide/partial)、样例 URL(「Learn more」文档+报告内样例)。
2. **全量修复(先于一切文书)**:partial 范围内**每一页**都要修,不是只修样例;链接类先删后 disavow(决策门槛见 [外链画像分析](../research/backlink-profile-analysis.md) 第四节:人工惩罚在列,属"应该 disavow"情形);UGC 类清历史存量+装治理;被黑类按安全事件先清后申诉。
3. **防复发**:修复必须含机制层(moderation/noindex/sponsored 属性/CI 校验),评审员会看"会不会再犯"。
4. **提交**:GSC 报告页「Request review」。前提红线:**没修完不提交**——过早提交被拒会拉长整体周期。
5. **等待**:多数案例**数天到数周**(官方口径);链接类最慢,可到 **6-8 周**(2026-10 检索:Google 官方"several days to weeks"+行业 3-21 天经验值+链接 6-8 周口径并存,取保守端做预期)。等待期**不要重复提交**。
6. **读回复**:报告条目消失=Revoked;仍列条目+新样例 URL=被拒,回到第 2 步。

### 3.2 Reconsideration 文书写什么(六要件)

1. 违规事实承认:具体说自己做了什么(买链就承认买链),不辩解不甩锅给前任/承包商;
2. 修复清单:做了什么、何时做的、覆盖哪些 URL/板块(全量,不是样例);
3. 证据:删除前后对比、disavow 文件链接与行数、takedown 记录、截图;
4. 未尽事项:删不掉的链接如实说明已列入 disavow;
5. 防复发机制:moderation 规则、sponsored 标注流程、监控告警;
6. 一句结语:请求重新评审。人写的、给人工评审员看的——模板腔和过度法律化措辞都是负信号。

**文书骨架(结构参考,内容必须站点事实)**:

```text
[站点] 关于 [动作类型] 的重新审核请求
1. 问题确认:我们在 [范围] 上存在 [违规事实,直陈]
2. 已完成的修复(截至 [日期]):
   - [动作 1]:覆盖 [N 个 URL/板块],证据 [截图/导出附件]
   - [动作 2]:disavow 文件已提交,含 [N] 个域,行级清单见附件
3. 无法完全移除的遗留:[哪些链接删不掉→已 disavow;哪些历史页→已 noindex]
4. 防复发:审核流程/出链标注规范/自动监控已上线([具体机制])
5. 恳请重新审核。[联系人]
```

- 长度纪律:两屏内讲完;附证据文件而不是把全量清单贴进正文;**如实**——评审员看过的申诉比任何顾问都多,虚报修复会被下轮样例直接戳穿。

### 3.3 被拒后再提

- 被拒的两大主因:**修复不全**(只修了样例 URL)与**文档不实**(说做了没证据)。报告里的新样例 URL 就是补修清单。
- 再提没有冷却期惩罚,但每次评审都要排队——把每轮被拒样例并进修复面,再提一次解决;反复空提是纯浪费周期。
- 3 次以上被拒且类型是 pure spam/scaled content:评估"重建 vs 继续修"(见 6.2)。

### 3.4 算法性损失:没有申诉通道

- 算法性损失**无 reconsideration 路径**——Google 官方口径:修复后需要算法**重新评估**,通常要数月,且恢复最可能出现在**下一轮 core update**(helpfulness 信号 2024-03 起并入 core 评估)。
- 2026 节奏参考:每年 3-4 次 core+1-3 次 spam(完整时间线与数据文件字段见 [seo-drift-monitoring](seo-drift-monitoring.md) 五)——掉了之后到下一轮 core 的间隔本身可能就是 2-4 个月,修复要抢在这个窗口内完成。
- 修复动作=内容质量工程(3.5),做完就是等+持续监测,不存在"催办"手段;任何承诺"加速算法恢复"的服务都是红牌。

### 3.5 内容质量工程(算法性恢复的实质)

1. **量裁**:按 GSC query/page 分层找出跌得最狠的页面族(方法沿用 drift-monitoring 五第 5 步);
2. **三选一逐页处置**:删(noindex/410,无保留价值)→并(301 进更强的同类页)→改(补第一手经验、数据、作者实体;刷新框架见 [content-refresh-playbook](../content/content-refresh-playbook.md));
3. **闸门**:规模化产出的页面族过 [agent-readiness](../technical/agent-readiness.md) 第 8 节硬门槛(唯一内容≥30%、standalone value test、渐进发布);
4. **E-E-A-T 载体**:作者页/审稿实体/可验证的一手证据——这是 core 评估的实质输入;
5. **完成度指标**:不是"改了多少页"而是"删并改后剩余页面族的平均质量信号"——用 [kpi-definitions](kpi-definitions.md) 的分层口径盯恢复前导指标(impressions 先于 clicks 回暖)。

## 四、负面 SEO 防御

### 4.1 2026 口径:威胁面重估

2026-10 检索共识:纯外链攻击**大都不再有效**(Google 自动忽略绝大多数垃圾外链);真实风险集中在**被黑(安全事件)> 可持续外链攻击 > 内容剽窃 > 表单/评论垃圾**。行业与官方口径均已收紧 disavow 使用(seoinbounds "probably not";SISL/Sharp Digital 2026 指南:仅人工惩罚或明确持续攻击才用)——与 [外链画像分析](../research/backlink-profile-analysis.md) 第四节既有门槛一致,本节不重复判据,只讲防御动作。

### 4.2 外链攻击识别与响应

- **识别**:外链档案突增尖峰(周环比异常)+锚文本集中于敏感词/精确匹配;用 [link-quality-rubric](link-quality-rubric.md) 走待复核流程,**先记录观察,不急批量 disavow**。
- **响应梯度**:被动中链→只监控;持续攻击且可见排名影响→导出人工核实→能删先删→删不掉才 disavow 台账化(格式与纪律沿用 [外链画像分析](../research/backlink-profile-analysis.md) 四节口径);收到"unnatural links"手动动作→按 3.1 流程,此时 disavow 是必选项。
- **风险自伤**:误杀真实链接的 disavow 比攻击本身更伤排名——整域 `domain:` 前先确认该域无正常链接。

### 4.3 内容剽窃

- 预防:新内容发布即提交索引(sitemap+IndexNow/即时索引通道),让原创先入索引;页面自引用 canonical。
- 处置:采集站排名反超时走 Google 法律移除(版权投诉)通道下架采集页;高价值资产加作者实体与结构化署名,降低"谁是原创"的判定模糊度。

### 4.4 伪造爬虫与爬虫攻击

- 伪装 Googlebot 的恶意爬虫(抓内容/撞接口):**反向 DNS 验证**(真 Googlebot 解析回 googlebot.com/google.com IP 段)后才放行;假 bot 在 CDN/WAF 层限速或拦截。
- 恶意高并发打爆服务器造成 5xx→索引受损:这属技术事件,走 drift-monitoring L4,别误判成惩罚。

### 4.5 垃圾提交与评论(UGC 防线)

- 表单/评论/个人资料页: moderation 队列+验证码+链接自动 `nofollow/sponsored`;UGC 区段 robots 策略收紧,防"用户生成垃圾"手动动作(partial 高发型)。
- 商家档案的虚假评论轰炸属平台侧攻击(GBP 口径),与搜索惩罚分开处置;**本地排名监控**用 [local-grid-ranking](local-grid-ranking.md) 的格点基线做前后对照。

### 4.6 防御基线(季度例行)

1. GSC 手动动作+安全报告巡检(零成本,最高优先);
2. 外链档案增量 diff(攻击尖峰的前导观测);
3. 反向 DNS 的 bot 日志抽查;4. 核心页面 `site:`/索引数抽测。基线快照先行的整套机制见 [seo-drift-monitoring](seo-drift-monitoring.md)(baseline/compare)。

### 4.7 攻击事件响应台账

确认或疑似攻击时,建一张台账(挂外链审计附录,载体同 [site-networks](../research/site-networks.md) 6.4 交付物口径):

| 字段 | 说明 |
|---|---|
| 检测日/首见日 | 攻击尖峰的最早观测(回溯增量 diff) |
| 攻击形态 | 外链突增/锚文本轰炸/采集站克隆/假 bot/表单灌水 |
| 规模与源 | 新增 referring domains 数、锚文本分布、源站/网段指纹 |
| 排名影响 | 攻击窗口前后 GSC 分层对比(impressions/position,不是 clicks) |
| 处置与日期 | 记录观察/takedown 发函/disavow 提交(何日、哪些域) |
| 复查日 | disavow 半衰期纪律:提交后按月回看,引用前复核 |

- 台账的两个用途:给 3.2 的 reconsideration 文书供证据(受攻击+已处置的完整链);给客户演示"记录和观察"不是不作为,是避免误杀的正确动作。

## 五、恢复期 SEO 策略(降权期间做什么/不做什么)

### 5.1 该做

- **假设先行**:先写单句假设模板("[Property] lost [X] starting [date] because [cause]…",模板沿用 drift-monitoring「五层协议」节),所有动作挂在假设下;
- **修复期内保持发布节奏**(质量不降的更新)——爬虫与评估都持续,沉寂本身是负信号;
- **技术面维持满分**:索引健康/CWV/结构化数据照常监控(恢复期最容易因疏忽引入二次技术损失);
- **渠道对冲**:邮件/社交/付费补搜索流量缺口,按 6.1 时长表给预算(恢复期=获客渠道冻结期,换算框架见 [site-networks](../research/site-networks.md) 4.2);
- **全量留痕**:每一步修复的 before/after——既是 reconsideration 材料(3.2)也是复盘资产;
- **盯前导指标**:impressions 回暖早于 clicks(kpi 分层口径),别用单一 clicks 曲线判生死。

### 5.2 不该做

- **不慌着换域名**:只有 pure spam 级不可逆损伤才考虑(且受罚域严禁 301 进新域,传染口径见 [site-networks](../research/site-networks.md) 6.3-D);
- **不批量删内容"表决心"**:删改走 3.5 的逐页三选一,无审计的大删除制造新薄内容问题;
- **不买链接救排名**:链接类处罚后再购链=递二轮证据;
- **不空提/重复提交 reconsideration**(3.3);
- **不无差别 disavow**(4.2);
- **不轻信"处罚 removal"速成服务**——算法性损失无催办通道(3.4),能承诺周期的都在卖幻觉。

### 5.3 沟通与预期管理

- 对内交付用 drift-monitoring「诊断清单细化」节的七段模板(What happened/Why/做什么/何时恢复+置信度/盯什么);恢复时长按 6.1 表给区间不给点值;
- 明确一句:**撤销(手动)/重评(算法)与排名回归是两个事件**——撤销后算法性遗留仍要等下一轮 core,这是客户预期错位的高发点(2.2 铁律 2)。

### 5.4 恢复期节奏表(30/60/90 天)

| 阶段 | 动作重心 | 里程碑判据 |
|---|---|---|
| 第 1-30 天 | 定性(二)+全量修复启动(手动类)/内容量裁(算法类);建立基线快照与分层监控 | 假设单句定稿;修复面清单冻结;(手动类)修复完成≥50% |
| 第 31-60 天 | 修复收尾+机制上线;(手动类)提交 reconsideration;算法类持续删并改 | 申诉在途/内容工程主要批次完成;前导指标止跌 |
| 第 61-90 天 | 等待期运营:按 5.1 维持发布与技术面;渠道对冲满负荷 | (手动类)收到 Revoked 或新样例;(算法类)赶在下一轮 core 前完成主要修复 |

- 表以"定性完成日"为 T0;90 天后仍未回暖不自动等于失败——对照 6.1 的场景行看自己处在哪个区间,而不是对照日历。

## 六、案例模式(常见处罚场景×恢复时长)

### 6.1 场景×处置×时长汇总表

| 场景 | 主处置路径 | 审核/重评周期 | 排名回归周期 | 口径 |
|---|---|---|---|---|
| 被黑注入垃圾页 | 清理+安全修复+申诉 | 数天-数周(最快类) | 快(评审撤销即回升) | 官方+行业共识 |
| 用户生成垃圾(partial) | 清存量+治理机制+申诉 | 数天-数周 | 数周 | 行业经验值 |
| 非自然外链(partial,买入) | 删链+disavow 台账+申诉 | **6-8 周**(链接类最慢) | 数周-数月 | 官方"links 更慢"+2026-10 检索 |
| 非自然外链(site-wide/PBN 联坐) | 同上+网络止血 | 同上 | **3-12 个月**(含网络传染处置) | [site-networks](../research/site-networks.md) 4.1/4.2(不重复) |
| Scaled content abuse | 删并改+渐进重发+申诉 | 数周,常见多轮被拒 | 1-2 个 core 周期 | 政策时间线见 agent-readiness 八 |
| 网站声誉滥用 | 撤/noindex 第三方板块 | 数周 | EEA 外板块降权解除;EEA 内改独立排序(不依赖申诉) | [site-networks](../research/site-networks.md) 4.3 EEA 分叉 |
| Pure spam | 整站重建评估;修复+多轮申诉 | 最长(常 3 轮+) | 撤销后仍需算法重评;多数走换域 | 行业经验值 |
| 算法性(core 打击) | 内容质量工程(3.5) | **无申诉**;数月重评 | **下一轮 core 才见分晓,通常数月起** | Google 官方(SEJ 转述) |
| 算法性(spam update 打击) | 同上,聚焦 spam 面修复 | 下一次 spam/core 重评 | 常快于 core 类 | 2026 年 3-4 次 core+1-3 次 spam 节奏 |

- 时长表是**预期管理工具**不是 SLA:所有区间以"修复完成时点"起算;修复拖多久,表就整体右移多久。

### 6.2 模式规律(给决策用)

1. **修复面决定周期**:partial 类(UGC/被黑)快,site-wide 与链接类慢——因为评审员要验证的是"全量修复";
2. **叠加是常态**:手动撤销+算法遗留=最长恢复线(外链 site-wide 与 scaled content 最典型);
3. **算法性恢复的杠杆在下一轮 core 前的修复窗口**:掉出 core 更新→立即量裁→在下一轮 rollout 开始前完成主要删并改([seo-drift-monitoring](seo-drift-monitoring.md) 五的更新数据文件就是为盯这个窗口);
4. **Yandex/百度不在本表**:滤镜/屏蔽时长数据沿用 [site-networks](../research/site-networks.md) 4.1,不重复。

### 6.3 时长数据的使用纪律

- **口径分层写**:官方区间(GSC 文档)、转述区间(SEJ/PPC Land)、行业经验值(机构博客)三档 credibility,引用时标明档位,不许混写;上表已在"口径"列分层。
- **幸存者偏差**:能写成案例的恢复多是"修好了"的样本;修废了的站沉默地消失——用此表做**上限乐观、下限保守**的区间沟通,不给点值。
- **起点不同不比表**:两个站的恢复周期可比,前提是修复完成度、匹配范围、是否有算法叠加三项一致;否则只做内部对照(修复前后自分比,见 [kpi-definitions](kpi-definitions.md) 口径)。
- 与 [site-networks](../research/site-networks.md) 4.1 直接代价表的关系:那表管"手法→代价"(事前劝阻),本表管"场景→恢复路径"(事后处置);两表在 PBN 联坐一行衔接,数字不重复维护。
