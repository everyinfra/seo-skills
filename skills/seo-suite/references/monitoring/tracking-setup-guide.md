# 排名追踪：设置与读数

> 要记录 AI 概览等 AI 功能里的出现与引用时，先读 [geo-evidence.md](../content/geo-evidence.md)。

## 用途

搭建或调整排名追踪时读。数据来自你自己选用的排名追踪工具（需要你自己的账号），本 Skill 不附带数据。结果填进 [rank-report.md](../../templates/monitor/rank-report.md)，告警阈值见 [alert-threshold-guide.md](alert-threshold-guide.md)。

## 一、它量的是什么

| | 排名追踪工具 | Search Console 平均排名 |
|---|---|---|
| 本质 | 在指定地点、语言、设备和时间，模拟一次未登录搜索得到的样本 | 所有真实展示中，本站最靠前结果位置的平均值 |
| 覆盖 | 只覆盖你设置的词和地点 | 覆盖有展示的全部查询，但罕见查询会被隐去 |
| 受什么影响 | 设置、抓取时间、SERP 实验 | 用户地点、设备、个性化、查询组合的变化 |
| 适合 | 受控对比、看竞品、看 SERP 版面 | 衡量真实表现（配合点击和展示） |

两者数字对不上是正常的，不要互相「校正」。

## 二、关键词集怎么选

来源按优先级：

1. Search Console 里已经有展示的查询（真实需求）。
2. 已上线或已规划页面的目标词。
3. 与转化直接相关的业务词、品牌词、和竞品的对比词。
4. 还没有页面、但计划覆盖的机会词，单独打标签。

规则：

- 每个词写明**目标 URL**。实际排名的 URL 与目标不一致，说明可能有几个页面在抢同一个词，或者目标页不够对题。
- 既没有需求证据、也没有页面计划的词，不追踪；泛到看不出意图的单个词，除非业务确实需要，也不追踪。
- 词数按预算和团队能处理的量定，不是越多越好。

## 三、分组标签

- 给每个词打多个标签，而不是只放进一棵树：主题簇、搜索意图（见 [keyword-intent-taxonomy.md](../research/keyword-intent-taxonomy.md)）、漏斗阶段、产品线、页面类型、优先级（T1 / T2 / T3）、品牌 / 非品牌、目标市场。
- 标签名固定下来，写进项目说明。报告按标签聚合：中位位置、进入前 3 和前 10 的词数、SERP 功能占有情况。

## 四、地域、语言、设备、搜索引擎

- 按真实目标市场设地点：国家、地区或城市。多个市场分开建项目，不混在一起算。
- 语言设置和目标用户一致。
- 移动端和桌面端分开追踪，两边结果常常不同。
- 搜索引擎按市场选：Google、Bing，以及当地用户实际在用的主流搜索引擎。
- 本地业务用城市级甚至更细的地点，并单独记录本地结果区块。

## 五、频率与每次记录的内容

- 频率：核心词每天、其余每周是常用起点，按预算和团队响应能力调整；新页面上线后的几周内，可以临时提高其目标词的频率。
- 每次记录：位置、实际排名的 URL、SERP 上出现了哪些功能（AI 概览、精选摘要、视频、本地结果、「其他用户还问了」等），以及本站是否占据其中之一。
- 记下工具的计位规则（SERP 功能是否算作位置）。换工具时，这往往是数字差异的主要来源。

## 六、误差与读数方法

- 个性化、地点、抓取时间、数据中心差异和 Google 的 SERP 实验，都会让单次读数有噪声。看多天中位数或周趋势，连续几次观测都变了才算变化。
- 一大批词同时变化：先查追踪设置和 SERP 版面，再查排名系统更新和站点技术问题。
- 同一个 URL 的所有词一起下跌：先查这个页面的状态码、noindex、canonical 和最近的改动。
- 位置没变但点击下降：去看 SERP 上新出现了什么功能。
- 手工抽查用未登录的浏览器，并注明地点和设备；手工结果也只是一个样本。

## 七、和 Search Console 对账

每月对照一次：同一批词在 Search Console 的平均排名与追踪位置，变化方向是否一致。长期背离时，检查地点设置、设备、目标 URL，以及是否有大量展示来自你没追踪的地区。

## 八、换工具

新旧工具并行一段时间，记录两边的系统性差异；拼接历史数据时，在报告里标明断点。

## 常见误区

- 把单日跳动当趋势。
- 把追踪工具里的位置当成所有用户看到的位置。
- 只追踪桌面端，或只追踪一个城市。
- 只看位置，不看 SERP 版面。
- 追踪的词没有对应的目标 URL。
